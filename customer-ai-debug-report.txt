2. ROOT CAUSE (two independent defects, not one)
===============================================================================
The reported error signature was confirmed by reproduction:
`node deploy/blitz/entrypoint.sh` yields exactly
    /opt/customer-ai/entrypoint.sh:2
    # ============================================================================
    ^
    SyntaxError: Invalid or unexpected token
i.e. the script reached Node as a JavaScript file.

(a) THE REPORTED SyntaxError — an operator-supplied container command replaced
    the image's CMD with `node /opt/customer-ai/entrypoint.sh`.
    The committed Dockerfile used CMD, which is REPLACEABLE at run time. The
    override most likely comes from a Render dashboard START COMMAND
    (dockerCommand) set on the service. render.yaml declares no dockerCommand,
    so a previously saved dashboard override still applies and wins over the
    image CMD. This could NOT have come from the Dockerfile: every version in
    git history was checked and none ever contained
    `CMD ["node", ".../entrypoint.sh"]` (HEAD was also verified clean).
    -> Fixed by declaring the entrypoint via ENTRYPOINT in the image. ENTRYPOINT
       is not replaceable by a plain command override, so the image now owns
       container startup.

(b) A SECOND, INDEPENDENT BLOCKER — the entrypoint was never made executable.
    deploy/blitz/entrypoint.sh is committed with git mode 100644
    (confirmed via `git ls-files -s`), and the Dockerfile had no chmod for it
    (only the `hermes` launcher got one). COPY preserves a non-executable file,
    so execve() of the entrypoint fails with EACCES. Reproduced:
    `./entrypoint.sh` at mode 0644 -> "Permission denied".
    Consequence: fixing ONLY the CMD->ENTRYPOINT swap would still have left the
    container dead with "permission denied" instead of the SyntaxError.
    -> Fixed by `RUN chmod +x /opt/customer-ai/entrypoint.sh`. The file is
       deliberately left 100644 in git; the mode is set in the image.

===============================================================================
- SHEBANG: kept `#!/usr/bin/env bash` (not switched to #!/bin/sh). The script
  has no other bash-only syntax (no [[ ]], no =~, no arrays, no local/source);
  its single non-POSIX dependency is `set -euo pipefail` (pipefail is not in
  POSIX; dash only gained it in 0.5.12). bash is an essential package and is

  is unchanged. It uses `exec`, so Node becomes PID 1 and receives
  SIGTERM/SIGINT/SIGHUP directly. The supervisor then spawns the real server
